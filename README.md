# Telemt-AWG-Double-hop

Интерактивный скрипт для быстрой настройки **double-hop прокси Telegram на [telemt](https://github.com/telemt/telemt)**
поверх туннеля **AmneziaWG**. Один и тот же скрипт настраивает оба сервера — зарубежный
**outbound** (выход к Telegram) и российский **inbound** (точка входа) — с базовой защитой VPS.

Заодно outbound работает как обычный **AmneziaWG-VPN** с веб-панелью [wg-easy](https://github.com/wg-easy/wg-easy).

## Архитектура (R1)

```
Клиент ──443/TCP──> INBOUND (РФ)                         OUTBOUND (за рубежом)
 (fake-TLS,          nftables DNAT :443                  telemt (на WG-IP 10.8.0.1)
  SNI=маска)           └─> AWG-туннель awg0 ───────────>  wg-easy (AWG-сервер) + nginx
                                                          telemt ──> Telegram DC
```

- **OUTBOUND** (за рубежом): wg-easy (AmneziaWG-сервер + панель) + nginx + **telemt** (+ его панель), всё в Docker.
  telemt делит netns с wg-easy и слушает на IP туннеля (`10.8.0.1`).
- **INBOUND** (в РФ): **не HAProxy, а L4-DNAT** — nftables форвардит весь `:443` в AWG-туннель на telemt.
  Так telemt сам терминирует клиентский TCP, и его анти-DPI (`client_mss`/`client_mss_bulk`, fake-TLS-прикрытие)
  реально доходит до телефона. Прикрытие `:443` даёт сам telemt (`unknown_sni_action`). Никакого Docker/HAProxy/nginx.

Клиент подключается к **inbound:443** по `tg://`-ссылке; трафик двойным прыжком идёт РФ → туннель → зарубеж → Telegram.

## ⚠️ AmneziaWG v3.0 ломает wg-easy — модуль пинится на v1.0

С **2026-07-30** `ppa:amnezia/ppa` отдаёт **AWG 3.0** — ломающее изменение netlink, несовместимое с awg-тулзами
внутри образа wg-easy 15.3.0 (`awg setconf: attribute type 14 has an invalid length`): интерфейс не поднимается
даже на чистой установке, и ни одна веб-панель AWG 3.0 пока не поддерживает. Поэтому скрипт **НЕ ставит модуль/тулзы
из PPA**, а собирает из git последние pre-3.0 версии:

- модуль ядра — тег `v1.0.20260725` (сборка DKMS) + `apt-mark hold` от возврата v3.0;
- `amneziawg-tools` (только на inbound, для host-`awg-quick`) — тег `v1.0.20260618-2` (`make && make install`).

Когда wg-easy запинит свои тулзы и AWG 3.0 стабилизируется — это правка в две строки (`AWG_MOD_TAG` / `AWG_TOOLS_TAG`).

## Что делает скрипт

1. **Безопасность VPS.** Новый sudo-пользователь вместо root, перенос SSH-ключей, отключение root-входа и (при наличии
   ключей) парольной аутентификации, `ufw` (deny по умолчанию), `fail2ban`, авто-обновления безопасности (`unattended-upgrades`).
2. **Ядро AmneziaWG.** Собирает пиновый v1.0-модуль из git (см. выше). Если на свежем VPS запущено старое ядро без
   заголовков — **сам обновляет ядро, перезагружается и продолжает установку неинтерактивно** (одноразовый systemd-юнит).
3. **OUTBOUND:** wg-easy (AmneziaWG) + nginx + telemt + панели, всё в Docker; доступ к панелям — по секретному пути
   (cookie-схема). TLS: самоподписанный / Let's Encrypt (HTTP-01) / Cloudflare (DNS-01). Может восстановить клиентов
   из бэкапа (см. ниже).
4. **INBOUND:** AmneziaWG-клиент (`awg0`) к outbound + nftables-DNAT `:443` → telemt через туннель (persist —
   `dhop-dnat.service`).

## Порядок развёртывания

1. **OUTBOUND** (`роль = outbound`, включить telemt). В конце печатает WG-IP telemt (`10.8.0.1`), порт, маску, секрет,
   готовую `tg://`-ссылку и адреса панелей. *(Перенос со старого сервера: положите бэкап клиентов в
   `/root/dhop-backup.tar.gz` ДО запуска — скрипт восстановит их в volume перед стартом wg-easy.)*
2. В панели wg-easy на outbound: **New Client → скачать `.conf`** для inbound.
3. **INBOUND** (`роль = inbound`): вставьте `.conf`, укажите WG-IP (`10.8.0.1`) и порт telemt.
4. Подключитесь по `tg://`-ссылке (`server=<inbound>`).

Без Telegram outbound работает как обычный AmneziaWG-VPN — роль `outbound`, отказаться от telemt.

## Маска fake-TLS и прикрытие

Маска (`tls_domain`) — это SNI, который отправляют клиенты (зашит в `tg://`-ссылку). Может быть чужим доменом или **вашим сабдоменом**.

**Рекомендуется свой сабдомен с A-записью на INBOUND-сервер** (напр. `cdn.example.com` → IP inbound): консистентно
(домен резолвится в тот же IP, куда подключается клиент), вы им управляете и можете ротировать. Чужой популярный домен
(`ozon.ru`) хуже — резолвится не в ваш IP и привлекает внимание. Домен должен поддерживать пост-квантовый
`X25519MLKEM768` для стабильного iOS (telemt синтезирует PQ-ServerHello сам, так что свой домен подходит); проверка —
[@Sni_checker_bot](https://t.me/Sni_checker_bot). Сам домен даже не обязан быть доступен по TLS — A-запись нужна только
для консистентности.

Прикрытие `:443` для чужого/сканирующего SNI выбирается при установке: **popular** (telemt фронтит мисдирект на сам
домен маски, его реальный серт) или **self-mask** (`reject_handshake` + ваш сайт-заглушка с реальным LE-сертом).

> Fake-TLS не защищает от активного зондирования самого прокси-SNI — это ограничение fake-TLS, не скрипта.
> Для максимального стелса нужен VLESS-Reality (отдельный стек).

**Медиа/iOS:** быстрая загрузка обеспечивается telemt-опцией `client_mss_bulk` (низкий MSS `client_mss="tspu"` только
на TLS-handshake для обхода DPI, нормальный — на payload). В R1 это работает, т.к. telemt сам терминирует клиента.
Внешние iptables-патчи (MEKO/MTproxy-reanimation) при этом не нужны.

## Требования

- Чистый **Ubuntu 22.04 / 24.04** или **Debian 11 / 12**, доступ root/sudo.
- Для Let's Encrypt — домен, направленный на сервер; для Cloudflare DNS-01 — API-токен («Edit zone DNS»).

## Запуск

```bash
curl -fsSLO https://raw.githubusercontent.com/ComradDart/Telemt-AWG-Double-hop/main/install.sh
sudo bash install.sh
```

> **Не запускайте через `curl ... | bash`** — скрипт интерактивный (`read`). Сначала скачайте файл, потом запустите.

На свежем VPS скрипт сам обновит ядро и **перезагрузится** — после ребута переподключитесь и следите за
`tail -f /var/log/vps_setup.log`; установка продолжится автоматически (ответы берутся из прошлого прогона).

## Доступ к панели (outbound)

wg-easy — SPA с абсолютными путями, поэтому используется схема на cookie: заход на `https://<домен>/<секретный_путь>`
ставит `HttpOnly`-cookie и редиректит на `/`; nginx проксирует на панель только запросы с верной cookie, всем остальным —
заглушка. Снаружи, не зная секретного пути, панель не видна. Секреты и адреса — в `/root/panel_path.txt`.

## Безопасность по умолчанию

- root-вход по SSH запрещён; парольная аутентификация отключается **только при наличии** SSH-ключа (защита от локаута);
- `ufw` открывает лишь текущий SSH-порт (из `sshd -T`, не хардкод 22), `80`/`443` и UDP-порт AmneziaWG;
- `fail2ban` (jail `sshd`, backend systemd); авто-security-обновления без перезагрузок;
- на inbound форвардинг разрешён точечно (`ufw route allow` только на telemt), глобальный FORWARD остаётся DROP.

> **Не закрывайте текущую SSH-сессию**, пока не проверите вход новым пользователем в отдельном окне — root по SSH уже отключён.

## Обновление, идемпотентность, логи

Скрипт можно запускать повторно — каждый шаг проверяет фактическое состояние и пропускает уже сделанное; секреты и
ответы хранятся в `/var/lib/vps_setup/` и переиспользуются. Логи с метками — в `/var/log/vps_setup.log`.

При повторном запуске на outbound: `docker compose pull` подтягивает свежие образы (`telemt:latest`, `nginx:stable`,
`wg-easy:15`), изменённый `config.toml` telemt форсирует рестарт контейнера. **Клиенты AmneziaWG в volume `etc_wireguard`
не пересоздаются** (никаких `down -v`) — заводить заново не нужно.
